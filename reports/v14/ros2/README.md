# V14 ROS2 제어 구조 — 검증 결과 (2026-09-27)

**ROS2 경로는 기존 in-process 제어 법칙을 수치적으로 재현했다. 하지만 PD를
PhysX 관절 드라이브로 옮기면 V14 5700 정책은 평지 3개 시드에서 모두 넘어졌다.**
원인은 ROS2가 아니라 액추에이터 모델 차이다: 정책은 IsaacLab 200 Hz explicit DCMotor로
학습됐다. 구조와 실행 방법: [설계](../../../docs/v14_ros2_design.md).

- 1로봇, `fixed_v2`, 노이즈 없음. 평지: 준비 2 s + 측정 12 s, 명령 0.4 m/s.
  계단 오르막: 단높이 15.714 cm 고정, 준비 0 s + 12 s, 명령 0.5 m/s.
- `ros2`: 정책·LPF·0.99 가드 ROS2 노드, PhysX implicit PD. `isaaclab`: 기존 in-process
  V13 action + explicit DCMotor(0.99 가드). 둘 다 같은 시드·같은 지형.
- HPC `ws1`, Slurm 작업 261–272 모두 `COMPLETED 0:0`([기록](hpc_jobs.txt)).
  작업258은 관절 순서 불일치로 브리지가 시작을 거부한 실행이다(아래). 종료 단계에서
  멈춰 취소했다.

## 해석과 한계

같은 상태에서 같은 위치 목표를 내므로 차이는 목표→토크 변환뿐이다. PhysX implicit PD는
스텝 끝 상태로 PD를 적분하고 DCMotor 속도-토크 곡선이 없다. 정책은 5 ms마다 고정되는
explicit PD 토크에 맞춰져 있다. 실기 모터 드라이버의 PD는 수 kHz로 돌기 때문에 어느 쪽이
실기에 더 가까운지는 이 실험으로 판단할 수 없다. 두 경우가 1로봇·3시드뿐이다.

- 관절 순서: PhysX articulation 순서는 `FL_HAA, FR_HAA, FL_HFE, FR_HFE, RR_HAA, RL_HAA,
  RR_HFE, RL_HFE, FL_KFE, FR_KFE, RR_KFE, RL_KFE`다. 첫 추정 순서로 실행한 작업258에서
  브리지가 이를 감지해 시작을 거부했고, 계약을 수정한 뒤 재실행했다.
- 넘어진 뒤 ROS2 노드 상태는 초기화하지 않는다. 지표는 첫 종료까지만 의미가 있다.
- 실시간(비-lockstep) 모드와 실기 드라이버 연결은 구현·검증하지 않았다.

## 다음 단계

PhysX PD 구조를 유지하려면 implicit actuator에서 정책 적응 훈련이 필요하다.
훈련 없이 기존 동역학을 유지하려면 ROS2 노드가 DCMotor 토크를 계산해 effort로 보내는
모드가 대안이다.

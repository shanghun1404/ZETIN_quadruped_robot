이후 방향 궤적 기록·고정 지형 판정·방향 적응 실험을 구현했다.

현재 20 mm 충돌 USD를 연구 기준으로 유지하고, 계단에서의 방향 추종을
먼저 진단하는 것을 권한다. 동일한 계단 집중 학습을 더 연장할 근거는 부족하다.

추가 학습 마지막 모델은 몸체 기준 전진 속도 평균이 0.472 m/s였지만,
12초 목표 방향 진행은 0.424 m였다. 방향 변화·경로 이탈이 기여했을 가능성이
있다는 추론이며, 현재 JSON에는 yaw 궤적이 없어 원인을 확정할 수 없다.
다음 실험은 루트 XY 경로·yaw·명령/실제 각속도를 기록하고, 그 결과로
방향 추종과 계단 진행 보상의 조정 여부를 정하는 것이 적절하다.
다리 간 최소 간격 개선만으로 이 문제를 해결했다고 판단하지 않는다.

## 측정 범위

다리 간 간격은 서로 다른 다리의 8개 캡슐 사이 24쌍을 계산한다.
발과 다리 사이 간격은 이 지표에 포함하지 않는다. 보행 간격은 50 Hz,
토크는 200 Hz로 측정하며 종료된 환경의 리셋 이후 상태를 제외한다.
따라서 50 Hz 사이의 순간 관통까지 없었다고 주장할 수 없다.
물리 접촉 허용 오차와 큰 충격 때문에 작은 음수 간격이 남을 수 있다.

시드 42는 후보 선택에 사용했다. 시드 43·44를 포함한 최종 평가에서도
지형 성능이 기준에 미달해 채택하지 않았다. 이 평가 묶음으로 튜닝한 후속
모델은 추가 시드에서도 검증해야 한다.

JSON의 `variant: v13`은 V13 토크 제어 경로를 뜻한다. V14 구성은
USD 해시·액터 해시·자기 충돌·지형 필터 메타데이터로 구분한다.

## 코드 검토

별도 검토자는 현재 구현에서 Critical·Important 결함을 발견하지 않았다.
다음 두 Minor 항목은 보류했다. 현재 저장된 평가 JSON에는 영향을 주지 않는다.

- 첫 측정 프레임에서 모든 환경이 종료되면 빈 간격 표본 때문에 평가가
  실패하며 생존 0 JSON이 저장되지 않는다.
- USD 통합 테스트는 필요한 같은 다리 필터의 존재를 검사하지만, 추가
  다리 간 필터·충돌 그룹의 부재까지 자동으로 검사하지는 않는다.

물리 관통 감소·질량 속성·실제 보행 결과는 코드 검토와 별도로 검증한다.
초기 후보용 구형 스크립트는 `config/experiments/v14_20260924/`에 보관했다.

검토 후 추가한 HPC 실패 재현 검사에서, Kit fast shutdown이 Python의
`SystemExit(1)`을 성공 코드 0으로 덮어쓰는 것을 확인했다(작업 131).
Kit에도 `post_uncancellable_quit(1)`을 지정한 후 동일한 없는 체크포인트
검사에서 종료 코드 1, 결과 JSON 미생성을 확인했다(작업 133).
평가 launcher는 기존 결과 덮어쓰기를 거부하고 실행 뒤 JSON 존재도 검사한다.
학습·프로브·USD 생성 진입점에도 동일한 Kit 종료 처리를 적용했다.
작업 배열 137의 세 경우 모두 오류 코드 1과 결과 미생성을 확인했다.
재현 스크립트는 `config/tests/verify_v14_eval_failure.sbatch`와
`config/tests/verify_v14_other_failures.sbatch`에 있다.

로컬과 HPC의 핵심 실행 파일 11개의 SHA-256 일치를 확인했다.
[코드 해시](code_sha256.json)와 원본 JSON을 함께 보관한다.

작업 134_4·134_5는 JSON 작성 후 launcher의 `output: unbound variable`로
실패했다. 실행 중 Bash 파일을 덮어쓴 배포 실수로, 이미 시작한 두 프로세스가
새 후처리 코드만 읽은 것이 원인이다. 해당 시드 43 평지·험지를 안정된
스크립트로 작업 146·147에서 재실행했으며, 모두 `COMPLETED 0:0`으로 끝나고
동일 수치가 재현됐다. 최종 집계는 `m5700_verified_*`를 사용한다.
최초 JSON은 이력을 위해 보존한다. 실행 중 파일 배포는 이후
버전별 경로나 원자적 파일 교체를 사용한다.

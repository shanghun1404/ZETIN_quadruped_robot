# C++ WBC and separate command process implementation plan

> **For agentic workers:** Execute inline using executing-plans and test-driven-development. Do not commit without the user's approval.

**Goal:** Preserve the existing control math while removing Python ADMM iteration overhead and preventing 50 Hz planning from blocking 200 Hz commands.

**Architecture:** A pybind11 and Eigen module executes all fixed ADMM iterations in one call with the GIL released. The hardware planner publishes timestamped plans at 50 Hz; a separate ROS process filters targets and computes hybrid commands from current measured joints at 200 Hz. Expired or invalid plans produce a latched hardware fault.

**Tech Stack:** C++17, Eigen 3, pybind11, NumPy, PyTorch CUDA, ROS 2 Jazzy.

**Spec:** The user approved the C++ WBC design and separate 200 Hz command loop in this conversation on 2026-10-17. This file records the implementation decisions for that approved work.

- Work in the existing isolated worktree. Preserve unrelated user edits and make no commits.

## Review focus

- Wrong shape or non-finite native inputs fail before entering Eigen.
- Disabled contacts, asymmetric torque limits and reused warm state retain reference results.
- Future, out-of-order, expired and malformed plans cannot produce an invalid command.
- Planner stalls and exceptions stop command publication and emit a hardware fault.
- Repeated walk transitions reset policy state without inference-tensor errors.

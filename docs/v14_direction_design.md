# V14 방향 복구와 계단 평가 수정

사용자는 V14 영상을 확인한 뒤 수정 및 HPC 진행을 승인했다. 기존 V14 작업
트리에서 직접 구현한다. 자동 커밋은 하지 않는다.

## 확인한 문제

1. 평가가 generator.curriculum=False로 모든 행의 난도를 무작위 생성했다.
   L5 행 선택만으로 15.714 cm 단높이가 보장되지 않는다.
2. 32개 환경을 8개 지형 타일에 중첩 배치했다. 물리 필터와 별개로 depth
   렌더링에 다른 로봇이 보일 수 있다. 기존 시각화 화살표도 제거할 필요가 있다.
3. 기존 성공 기준은 방사형 최대 거리와 몸체 최대 상승으로, 옆 방향 이탈과
   되돌아 내려오는 사례도 통과할 수 있다. 최종 지면 높이와 방향 진행을 측정한다.
4. yaw=0 속도 명령에는 누적된 방향 오차 정보가 없고, 기존 yaw 보상의
   std=2.0 rad/s는 오차에 둔감하다. 같은 MLP 입력의 yaw 명령으로 복구 정보를 준다.

## 수정

- 기존 평가 모드는 재현용으로 보존하고 `--protocol fixed_v2`를 추가한다.
  계단은 한 행, 환경 수만큼 열, 단높이 범위의 양 끝을 지정 높이로 고정한다.
  각 환경은 서로 다른 타일에 배치하고 debug_vis=False로 만든다.
- XY/자세/명령/속도/로봇 바로 아래 지면/생존 궤적을 기록한다.
  보강된 계단 통과는 생존, 최종 전진>=2.1 m, 최종 지면 변화>=2단-2cm,
  전 구간 횡이탈<=0.6 m, 전 구간 heading 오차<=60도로 정의한다.
  전체 계단 통과는 전진>=3.6 m 및 전체 높이 도달을 별도로 보고한다.
- V14용 command subclass는 episode 시작의 방향과 XY를 보존한다.
  yaw 명령 = clip(1.5*heading_error + 0.6*오른쪽 횡이탈, ±0.4 rad/s).
  명령 재샘플링 시 목표 선을 초기화하지 않는다. 정지 명령에서는 yaw도 0.
- 방향 적응 후보는 V14 5700에서 시작하고 yaw 추종 std=0.25, weight=7.5로
  수정한다. optimizer는 초기화하고 학습률은 고정 3e-4로 둔다. 기존 자세/보행/토크 가드·USD는 유지한다. 보상에 관측할 수 없는
  절대 yaw 목표를 직접 추가하지 않는다. 32개 환경, 짧은 파일럿 후 판단한다.
- 파일럿 훈련은 타일 중첩 방지를 위해 시작 지형 L0, 열 수>=환경 수,
  환경별 열을 고정하고 기존 난도 커리큘럼을 사용한다.

## 제약과 판단

학습 및 시뮬레이션은 모두 HPC `ssh ws1`, Slurm qos=admin. GPU 1개/작업,
동시에 최대 2개. 원본 USD 및 이전 결과는 보존한다. V13의 0.99 토크 가드 유지.
수정 전 V14, 조향만 적용한 V14, 재학습 V14를 새 평가 조건에서 비교한다.
이전 25/96 같은 집계는 무작위 단높이의 과거 프로토콜 결과이며 고정 L5의
성공률로 인용하지 않는다. 후보는 방향·계단 성능이 좋아지고 평지 생존과 토크
한도 유지가 확인된 범위에서만 채택한다. 전체 지형 검증 전에는 파일럿으로 표기한다.
